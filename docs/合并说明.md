# 合并说明 · tvbox.json / tvbox-wmz.json

把仓库内 13 个独立配置 + 1 个外部源（wmz）合并为可直接接入 TVBox 的配置。

- 生成命令：`python tools/merge_config.py`
- 产物：
  - `tvbox.json` — 436 站（**主用**，单地址接入；死链与重复源见 `docs/源体检报告.md`）
  - `tvbox-wmz.json` — 95 站，22 KB（wmz 原版，补齐主配置收不了的 jar 专属站）
  - `repo.json` — 多仓入口，11 个仓库可选
- 订阅地址：`https://raw.githubusercontent.com/xiaolei7172/tvbox/master/tvbox.json`

---

## 一、为什么需要合并

仓库原有 13 个配置各自独立，用户要在客户端里反复切换地址才能用到不同来源的源。

但合并有硬约束：**TVBox 一份配置只能指定一个 spider**。

`spider` 是客户端的 jar 包，站点里的 `"api": "csp_XXX"` 就是调用 jar 内部的 `XXX` 类。不同 jar 提供不同的类集合，混用会直接加载失败。所以必须先选一个 jar，再谈合并。

---

## 二、spider 选型：实测九选一

从每个 jar 的 `classes.dex` 中直接提取 `com/github/catvod/spider/*` 类名（dex 里类名是明文，不需要反编译），得到每个 jar 的**真实能力边界**。下表按「现配置 493 站 + wmz 95 站 = 588 站」这个总量实测：

| jar | 类数 | 体积 | 能收（/588） | 结论 |
|---|---:|---:|---:|---|
| **`spider.jar`** | **172** | **1.85 MB** | **572** | **选中** |
| `wmz.jar`（261109.jar） | 190 | 2.03 MB | 527 | 第二 |
| `fty.jar` | 99 | 0.61 MB | 383 | |
| `pg23a94bb_upgraded.jar` | 257 | 11.18 MB | 381 | 类最多但几乎不重叠 |
| `XYQ.jar` | 74 | 0.38 MB | 378 | |
| `pg_upgraded.jar` | 255 | 2.78 MB | 377 | |
| `custom_spider.jar` | 44 | 0.25 MB | 360 | fongmi 极简版 |
| `XBPQ_upgraded.jar` | 30 | 0.63 MB | 344 | |
| `fan.txt` | 53 | 1.35 MB | 314 | 类名带 Guard 后缀，不通用 |

### 关键发现：类多 ≠ 收得多

`wmz.jar` 有 190 个类，比 `spider.jar` 的 172 个还多，但能收的站点反而少 45 个。

原因是两者只有 117 类重叠，各自独有：

```
spider.jar 独有 55 类：XBPQ / XYQHiker / AppFox / YST / Youtube / SportQiutong
                      / PanWebShare 系列 / Anime* 六件套 …
wmz.jar   独有 73 类：AList / Pan115 / WebDAV / Libvio / Juying / GuanYing
                      / HDMoli / HJZhenCai / Ixcyy / JuheSo / Duoduo / DSX …
```

`spider.jar` 独有的那批恰好是仓库里站点密度最高的部分（`XBPQ` 一个类撑起 20 多个站，`XYQHiker` 撑起 12 个），所以选它。

> **代价**：`wmz` 有 16 个站依赖 `wmz.jar` 独有的类，主配置装不了 —— 这就是 `tvbox-wmz.json` 存在的理由。

## 三、wmz 源怎么合的

wmz 的订阅地址返回的不是明文 JSON，而是 `YmFzZTY0**` 前缀 + 整段 base64：

```
YmFzZTY0**eyJzcGlkZXIiOiJodHRwczovL3Jhdy5naXRjb2RlLmNvbS8…
```

`tools/refresh_wmz.py` 负责解码，并在 CI 里每天刷新快照（配置 + 配套 jar 同步升级，缺一不可）。

### 重叠度很高

wmz 的 95 个站里，**80 个与现有配置重复**：

| 情况 | 数量 | 处理 |
|---|---:|---|
| key 相同且 `api` + `ext` 完全一致 | 48 | 跳过（同一个站） |
| key 相同、`api` 或 `ext` 不同 | 14 | 跳过（同站点的另一种实现） |
| `csp_` 类不在 `spider.jar` 里 | 16 | 跳过（装不了，留在 `tvbox-wmz.json`） |
| 名称归一化后相同 | 3 | 跳过（「快映 • 4K」vs「💯快映｜4K臻享」） |
| `(api, ext)` 完全相同 | 1 | 跳过 |
| **真正新增** | **13** | **收录** |

实际新增的 13 个：鬼鬼盘搜、玩耦 4K、欧哥 4K、咕噜、山楂、悦听吧、魔方、电影天堂、一起看、搜4K、光鸭网盘、咖啡体育、裤硪/听海音乐。

### 「我的网盘」为什么没加进来

wmz 有 9 个「我的丨夸克/UC/百度/迅雷/天翼/123/阿里网盘」，看着很值，但查下来现有配置里**已经有了同样的站**（只是名字写成「夸克 • 网盘」），`api` 和 `key` 完全一致，属于真重复。

只有 115 网盘、AList、WebDAV 是 wmz 独有 —— 而这三个类恰好不在 `spider.jar` 里，只能去 `tvbox-wmz.json` 用。

### 跨配置去重只对 wmz 打开

不同配置给同一个源起名风格差异极大：

```
现有配置：  快映 • 4K           wmz：  💯快映｜4K臻享
```

所以对 wmz 启用了**名称归一化去重**（去符号 → 逐层剥掉「蓝光/秒播/臻享/4K/网盘/合集」等营销后缀 → 小写比较），两边都收敛成「快映」。

但这套逻辑**只对 wmz 生效**。仓库内原有 13 个配置彼此 key 体系一致，直接按 key/name 去重就够；对它们启用归一化反而会把「本地视频」「爱看」这类本来合法的站误判成重复（实测会误杀 14 个）。

## 四、555 电影：重写规则

仓库里原有两条 555 的规则，**全部失效**：

| 文件 | 问题 |
|---|---|
| `js/555电影[V2].js` | 走 `/api.php/app/video`，该接口已 404（站点换成纯 HTML 的苹果CMS V10） |
| `js/555影视[飞].js` | 走 `/vodshow/fyfilter.html`，已 404；搜索走 `/index.php/ajax/suggest`，返回空 |

两条都已删除，替换为新建的 `js/555电影.js`。

### 域名会自动跟着走

555 的真实站点域名一直换，入口固定在发布页 `https://www.555dyy.top`。发布页把当前域名池放在一个不显眼的属性里：

```html
<div id="domainData" data-info="eyJzaXRlX21haW4iOiJ3d3cuNTU1azAyLmNvbSIs…"></div>
```

base64 解出来是：

```json
{"site_main":"www.555k02.com","site_1":"www.5k27.top",
 "site_2":"www.5k40.com","site_3":"www.555k09.com"}
```

规则的 `hostJs` 每次加载都去读这个属性，域名换了不用改规则。四个域名实测全部可用。

### 页面结构与 URL 模板

站点是标准苹果CMS V10，URL 是「字段用横线隔开、空字段留空」的定长格式：

```
列表 /vodshow/{tid}-{area}-{by}-{class}-{lang}----{page}---{year}.html
搜索 /vodsearch/{关键词}----------{page}---.html
详情 /voddetail/{id}.html
播放 /vodplay/{id}-{sid}-{nid}.html
```

横线数量是精确的：`/vodshow/1--------1---.html`（tid 后 8 个横线到页码），多一个少一个都是 404。这个模板是逐段枚举出来的，不是猜的。

**列表页和搜索页的卡片结构不一样**，这是最容易踩的坑：

| | 容器 | 标题 | 链接 |
|---|---|---|---|
| 列表 | `a.module-poster-item`（自身是 `<a>`） | `.module-poster-item-title` | 自身 `href` |
| 搜索 | `div.module-card-item` | `.module-card-item-title` | 内部 `a.href` |

所以规则里 `一级` 和 `搜索` 各写一套选择器，不能共用。

### 播放地址：前 12 集直连，其余交给嗅探

播放页把真实地址放在一段脚本变量里：

```html
<script>var player_aaaa={"flag":"play",…,"url":"https://cdn3.ryplay3.com/…/index.m3u8",…}</script>
```

实测单集解析耗时 **0.74 秒**。一部 46 集的剧全解析要 34 秒，必然超过客户端二级超时。

所以采用混合策略：

- **前 12 集**在二级阶段就解析出 m3u8 直链 → 点开即播
- **第 13 集起**保留播放页地址 → 交给客户端的 Web 嗅探

单集电影只有 1 集，永远走直连，体验最好；长剧前面几集秒开，后面的靠嗅探兜底。

### 多线路只取一条

详情页有 11 条线路，每条 46 集，内容基本相同。规则里选出**集数最多的那一条**（`.module-play-list` 分组后比较长度），避免同一个剧在列表里出现 11 倍重复。

## 五、合并规则

### 站点收录

| 站点类型 | 判定 | 是否收录 |
|---|---|---|
| `csp_XXX` | `XXX` 在 `spider.jar` 的 172 个类中 | ✅ |
| `csp_XXX` | 不在上述集合 | ❌ 加载必失败 |
| `./lib/drpy2.min.js` + `ext: ./js/*.js` | JS 源，客户端 QuickJS 执行 | ✅ 全收 |
| `*.py` | Python 源，客户端 Python 运行时 | ✅ 全收 |
| `http(s)://...` | 直连采集 API | ✅ 全收 |

js / py / http 三类**不经过 jar**，与 spider 选型无关，全量并入 —— 这是站点数能上 500 的主因。
之后又跑了一轮源体检，剔掉 27 个死链 + 43 个重复源，最终 436 站。

### 去重与过滤

1. **key 唯一** —— TVBox 以 key 作站点标识
2. **name 唯一** —— 避免列表出现两个「豆瓣」
3. **跨配置归一化去重** —— 仅对 wmz 启用，见第三节
4. **ext 断链剔除** —— 指向的本地规则文件不存在则丢弃
5. **无 api 剔除**

本次顺手清掉了 8 处历史断链：`js.json`、`0825.json` 里 `./lib/wogg.json`、`./lib/wog.json` 统一改指已存在的 `./json/wogg.json`；`西门[V2]` 的规则文件上游根本不存在，直接从源头移除该站。

### 直播源

按「协议无关 + 去尾斜杠」的 URL 规范化去重（`http://x/a` 与 `https://x/a/` 视为同一条），并校验本地文件存在性。结果 14 条。

### 解析

剔除 `url` 为空或为 `Demo` 的占位项，按 `(name, url, type)` 去重，得 48 个。

## 八、维护

`tvbox.json`、`tvbox-wmz.json`、`repo.json` 已接入每日 Actions：

```
刷新 wmz 源 → 合并配置 → 体检 → 提交推送
```

上游 jar 被换掉时，`merge_config.py` 会重新从 dex 提取白名单，不用手工维护。

需要手动重跑时：

```bash
python tools/refresh_wmz.py     # 可选，同步 wmz 的配置和 jar
python tools/merge_config.py
git add tvbox.json tvbox-wmz.json repo.json && git commit -m "更新合并配置"
```

## 九、已知局限

1. **wmz 的 16 个站主配置装不了** —— `AList`、`Pan115`、`WebDAV`、`PanShare`、`Libvio`、`Juying`、`Wn4k`、`GuanYing`、`HDMoli`、`HJZhenCai`、`Ixcyy`、`Mipansou`、`Yinhai`、`JuheSo`、`SouJu`、`Bdjmcc`。要用请切 `tvbox-wmz.json`。
2. **`0825.json` 的 77 个 `csp_Wobg` 站、`367.json` 的 71 个 `csp_*Guard` 站**同样因 jar 不兼容未收录。
3. **直连 API 约半数失效** —— 52 个 http 采集站抽样仅 52% 可达。域名更换频繁属 TVBox 生态常态，保留是为后续可能恢复。
4. **555 电影第 13 集起依赖 Web 嗅探** —— 若客户端不支持嗅探，长剧后面几集播不了；改规则里的 `i<12` 可以调大覆盖范围，代价是二级加载变慢（每集约 0.74 s）。
5. **未做全量播放验证** —— 只验证到「配置可加载、依赖齐全、选择器命中、域名未失效」，未逐个实测播放。
