# 合并说明 · tvbox.json

把仓库内 13 个独立配置合并为一份可直接接入 TVBox 的单一配置。

- 生成命令：`python tools/merge_config.py`
- 产物：`tvbox.json`（110 KB，493 站）+ `repo.json`（多仓入口）
- 订阅地址：`https://raw.githubusercontent.com/xiaolei7172/tvbox/master/tvbox.json`

---

## 一、为什么需要合并

仓库原有 13 个配置各自独立，用户要在客户端里反复切换地址才能用到不同来源的源。合并后一次接入即可。

但合并有硬约束：**TVBox 一份配置只能指定一个 spider**。

`spider` 是客户端的 jar 包，站点里的 `"api": "csp_XXX"` 就是调用 jar 内部的 `XXX` 类。不同 jar 提供不同的类集合，混用会直接加载失败。所以必须先选一个 jar，再谈合并。

---

## 二、spider 选型：实测六选一

从每个 jar 的 `classes.dex` 中直接提取 `com/github/catvod/spider/*` 类名（dex 里类名是明文，不需要反编译），得到每个 jar 的**真实能力边界**：

| jar | 类数 | 体积 | 合并后能收的站点 | 相对 `spider.jar` |
|---|---:|---:|---:|---|
| **`spider.jar`** | **122** | **1.85 MB** | **496** | 基准 · **选中** |
| `pg_upgraded.jar` | 132 | 2.78 MB | 450 | 类更多但几乎不重叠 |
| `pg23a94bb_upgraded.jar` | 128 | 11.18 MB | 451 | 覆盖 pg 的 96.9%，体积代价过高 |
| `XYQ.jar` | 38 | 0.38 MB | 382 | 缺 XBPQ / PanWebShare / Sports* |
| `custom_spider.jar` | 41 | 0.25 MB | 369 | fongmi 极简版 |
| `fan.txt` | 50 | 1.35 MB | 371 | 饭太硬，类名带 Guard 后缀，不通用 |

### 关键发现：两个大包几乎不互补

```
spider.jar ∩ pg_upgraded.jar = 20 类
spider.jar 独有 = 102 类
```

`pg_upgraded.jar` 虽然类数更多（132 > 122），但其中 102 个是 `spider.jar` 没有的，同时缺了 `spider.jar` 的 102 个 —— 它**不是超集**，而是另一套体系。

`spider.jar` 独有的大项包括：`XBPQ`（小米小爆脾气系列，多配置在用）、`XYQHiker`（香雅情 Hiker，12 个站点）、`PanWebShare`（7 个网盘站点）、`Sports*`（6 个体育源）、`Short*`（7 个竖屏短剧）、`App*` 系列（20+ 个 APP 源）。

这些恰好是仓库里站点密度最高的部分，所以选 `spider.jar`。

> 副作用：`0825.json`（pg 包）的 77 个 `csp_Wobg` / `csp_TGYunPan` 类站点、`367.json`（远程 moyu.php）的 71 个 `csp_*Guard` 类站点无法并入。它们只在各自的 jar 下可用，合并版不收录。

## 三、合并规则

### 站点收录

| 站点类型 | 判定 | 是否收录 |
|---|---|---|
| `csp_XXX` | `XXX` 在 `spider.jar` 的 122 个类中 | ✅ 收录 |
| `csp_XXX` | 不在上述集合 | ❌ 排除（加载必失败） |
| `./lib/drpy2.min.js` + `ext: ./js/*.js` | JS 源，客户端 QuickJS 执行 | ✅ 全部收录 |
| `*.py` | Python 源，客户端 Python 运行时 | ✅ 全部收录 |
| `http(s)://...` | 直连采集 API | ✅ 全部收录 |

js / py / http 三类**不经过 jar**，因此与 spider 选型无关，全量并入。

### 去重与过滤

1. **key 唯一** —— TVBox 以 key 作站点标识
2. **name 唯一** —— 避免列表出现两个「豆瓣」；同名保留来源优先级更高的（顺序：`jsm` > `dianshi` > `xiaosa` > 其余）
3. **ext 断链剔除** —— 指向的本地规则文件不存在则丢弃（本次剔除 1 个：`影视 | 西门[V2]`）
4. **无 api 剔除**

### 直播源

按「协议无关 + 去尾斜杠」的规范化 URL 去重（`http://x/a` 与 `https://x/a/` 视为同一条），并校验本地文件存在性。

结果 14 条：`./tvboxtv.txt`、`./tvlive.txt`、`./list.txt`、`./listx.m3u`、`./listx.txt`、`./radio.txt`、`./livex.m3u`、`./yo21.txt`，以及 `tv.iill.top` 的 3 条 m3u、OK影视本地代理 2 条、1 条外部 iptv.php。

### 解析

剔除 `url` 为空或为 `Demo` 的占位项，按 `(name, url, type)` 去重，得 48 个。

## 六、维护

原配置每日由 Actions 自动更新；**合并配置不会自动更新**，需要手动重跑：

```bash
python tools/merge_config.py
git add tvbox.json repo.json && git commit -m "更新合并配置"
```

如需自动化，可在 `.github/workflows/run.yml` 的 verify 步骤后追加一步执行合并脚本，
但要先确认上游更新没有引入新的 `csp_` 类 —— 若上游换了 jar，白名单会失效。
脚本每次运行都会打印白名单来源与实际 jar 的类数，便于核对。

## 七、已知局限

1. **直连 API 约半数失效** —— 52 个 http 采集站中抽样仅 52% 可达。域名更换频繁，属 TVBox 生态常态，保留是为后续可能恢复。
2. **`367.json` 与 `0825.json` 的 jar 专属站点未收录** —— 见第二节副作用说明。若需要这些源，请单独使用原配置。
3. **JS 源质量取决于站点存活** —— 246 个 JS 源的规则文件都在，但目标站点是否可用需实际播放验证。
4. **未做播放链路验证** —— 本次仅验证到「配置可加载、依赖齐全、API 可达」层面，未逐个实测播放。
