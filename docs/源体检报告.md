# 源体检报告 · 死链与重复清理

> 生成时间：2026-11-09　｜　对象：`tvbox.json`（全量合并配置）　｜　结果：**506 → 436 站，删除 70 条**
>
> 注：之后又做了一轮顶层去重与失效加速站本地化，`tvbox.json` 现为 **434 站**，见 [合并说明 · 第三轮](合并说明.md)。

## 一、怎么测的

直接把每个源"HTTP 打一下"在这台机器上不可行 —— 实测本地出口访问不了大部分境外影视站，
而且本机 DNS 被污染（`www.olevod.com` 被解析到 `148.163.48.215`，`www.bugutv.org` 被解析到 Facebook 的 `31.13.88.26`）。照这种结果删源，会把一堆活得好好的站误杀。

所以改成分三路取证，每条结论都要有两条以上独立证据：

| 证据 | 做法 | 作用 |
|---|---|---|
| 域名存在性 | 阿里 DoH + 腾讯 DoH 查询，再用 114DNS / 8.8.8.8 / 223.5.5.5 裸 UDP 交叉验证 | 五处全 `NXDOMAIN` 才判死 |
| 接口协议 | type 0/1 直连站点 `?ac=list` / `?ac=detail&wd=`，校验返回是不是真的 JSON/XML 列表 | 确认"活着且能用"，不作死亡依据 |
| 上游在册度 | 该域名在本仓库其余 335 个配置/规则文件里被引用的文件数 | 还在被人用的，一律不删 |

判定口径：

- **死链**：域名在 5 个解析器上全部没有记录（域名已注销/停用）→ 删除
- **重复**：`api + ext` 完全一致，或规则文件 md5 一致，或同一站点只换了名字/镜像 → 只留一个
- **不可判定**：域名存在但本机访问不了（多为境外站）→ **保留**，只在报告里列出来

## 七、怎么复跑 / 怎么回滚

```bash
# 1) 重新探测（约 3 分钟，产出 tools/probe_result.json）
python tools/probe_sites.py
# 2) 三路取证定性（约 30 秒，产出 tools/audit_result.json）
python tools/audit_sources.py
# 3) 按 blocklist 重新合并
python tools/merge_config.py
```

删除不是硬编码在 json 里的：所有被删的源都记在 **`tools/blocklist.txt`**，合并脚本 `add_sites()` 在入表前按 key 过滤。想恢复某一个源，把那行注释掉再跑一次合并即可；
上游每天更新带来的新站也不会被这份清单误伤。

## 八、顺手修掉的一个坑

合并脚本原来的 `(api, ext)` 去重是把 `dict` 直接 `str()` 比较，而同一个 ext 对象在不同配置里键顺序不同 → 精确重复判不出来（这次 20 条精确重复就是这么漏进来的）。
已改成 `json.dumps(ext, sort_keys=True)`，以后再合并不会重复收录。
